# libSceFontGs technical debt

### Functional

- [sceFontGraphicsGnmDrawupFillTextureImage](../../../core/libs/prx/libSceFontGs/Export.cpp) (libSceFontGs) - returning `FontGsInvalidParameter` (`0x80460002`) when the `output` pointer is unwritable via `GuestCopyOut_nid_no_patch` on initial zeroing or record write-back is a host-safety fallback preserving host errno; console behavior on unmapped pointers is not measured.

### Unknown function info

- [sceFontSelectGraphicsGnm](../../../core/libs/prx/libSceFontGs/Export.cpp) (libSceFontGs) - index 0 returns the Gnm backend table laid out as in the PS4 10.71 module (0x34040: header, 21 opcode entries, list descriptor), with a process-global instance slot (0x3ed60) and the enumerate function (0x47c0); other indices return `nullptr`. Opcodes 0x47000002 (terminate, 0x5ec0, a bare `ret`) and 0x47000005 (surface texture, 0xdf40) are ported, and 0x47000003 and 0x47000004 hold the module's constants. The other 17 handlers, 0x47000001 init (0x47e0) included, throw `sceFontSelectGraphicsGnm_backend_<opcode>` through `NotImplemented_nid_no_patch`, so creating a graphics service with this backend throws at init. Off-console, the table matched the decrypted module except for its pointers, and the module's enumerate with libSceFont's fill (0x2c5c0) fills the same dispatch slots from both tables. Not checked on a console.

### Not console-verified

- [sceFontGraphicsGnmSurfaceInit](../../../core/libs/prx/libSceFontGs/Export.cpp) (libSceFontGs) - Neo mode is not console-measured, and the tiling branch for a macro tile over 1 KiB (0x266bc) throws through `NotImplemented_nid_no_patch`; no accepted tile mode and element size reaches it. Only the paths SurfaceInit can reach are ported: one fragment, one mip level, depth 1, pitch 0, no flags, so helpers 0x22550 and 0x22910 and the fragment, mip, pitch and block-compressed tiling branches are left out. Its result was compared with the PS4 10.71 body (offset 0x41e0) and its DataFormat, `Texture::init`, tiling and base-address helpers; it matched that machine code run off-console on about 55 million base and Neo configurations, and the console's own function in base mode on the six test configurations.
- [sceFontSelectGraphicsGnm opcode 0x47000005](../../../core/libs/prx/libSceFontGs/Export.cpp) (libSceFontGs) - the surface texture handler (0xdf40) and its helpers (0x22d40, 0x23060, 0x232a0, 0x22c30, 0x25480, 0x25b10, 0x25430, 0x25ce0) follow the PS4 10.71 bodies, not checked on a console. It sets the base and clears the metadata address of the Gnm texture in the surface copy, builds the 8-dword T# at texture object +0x40, and gives one-channel formats the selects (1, 1, 1, channel) and RG8 (R, R, R, G). Where the macro tile lookup fails, the bank mask uses what the original leaves in `cl` (a popcount or the array mode); SurfaceInit's base setter now does the same. Off-console, it matched the decrypted handler on 3000000 random texture, object and base inputs, base and Neo bits included, and on 200000 textures built by SurfaceInit.
- [sceFontGraphicsGnmSurfaceInit tiling tables](../../../core/libs/prx/libSceFontGs/Export.cpp) (libSceFontGs) - `GnmTileModes` and `GnmMacroTileModes` are built from named GB_TILE_MODE/GB_MACROTILE_MODE fields with the shifts of [gfx_7_2_sh_mask.h](https://github.com/torvalds/linux/blob/d48723711bae9b8cdc56719c448ba42fef28cbee/drivers/gpu/drm/amd/include/asic_reg/gca/gfx_7_2_sh_mask.h#L4221-L4548) and the values of [gfx_7_2_enum.h](https://github.com/torvalds/linux/blob/d48723711bae9b8cdc56719c448ba42fef28cbee/drivers/gpu/drm/amd/include/asic_reg/gca/gfx_7_2_enum.h#L5159-L6224). The Neo ALT_PIPE_CONFIG (bits 27-31, P16 = 0x12) and alt bank fields (bits 8-13) are not in AMD headers; their layout matches RPCSX [tiler.hpp](https://github.com/RPCSX/rpcsx/blob/e8ae1481ab7ba04d5c6bef89dd852aabba2c88ff/rpcsx/gpu/lib/amdgpu-tiler/include/amdgpu/tiler.hpp#L94-L169). Thickness is the micro-tile depth per array mode, and a degraded tile mode is the first Thin or Thick entry of that array mode.

- [sceFontGraphicsGnmSurfaceInit tiling rules](../../../core/libs/prx/libSceFontGs/Export.cpp) (libSceFontGs) - the array mode classes use the [gfx_7_2_enum.h](https://github.com/torvalds/linux/blob/d48723711bae9b8cdc56719c448ba42fef28cbee/drivers/gpu/drm/amd/include/asic_reg/gca/gfx_7_2_enum.h) ARRAY_MODE values. `GnmIsMacroTiled` is 2D, 3D or PRT (4 and up) and `GnmIsPrt` the six PRT modes. `GnmHasThinOrThickFallback` is a tiled mode other than the XTHICK and PRT THICK ones. `GnmTileModeHasBanks` is a GB_TILE_MODE entry that is macro tiled and not ROTATED; only those keep bank bits in a base address. `GnmDegradeArrayMode` is AddrLib's [DegradeLargeThickTile](https://gitlab.freedesktop.org/mesa/mesa/-/blob/4fa244fddfebb21378042556862e197284ef65ac/src/amd/addrlib/src/core/addrlib1.cpp#L3749-3807) with a 1 KiB row: when 8 x 8 x thickness texels do not fit one row, a thick mode becomes the thin mode of its family, an XTHICK mode whose half fits becomes THICK, and 1D THICK stays.

- [sceFontGraphicsGnmSurfaceInit format word](../../../core/libs/prx/libSceFontGs/Export.cpp) (libSceFontGs) - `GnmTextureFormatWord` fills the CB_COLOR_INFO fields of [gfx_7_2_sh_mask.h](https://github.com/torvalds/linux/blob/d48723711bae9b8cdc56719c448ba42fef28cbee/drivers/gpu/drm/amd/include/asic_reg/gca/gfx_7_2_sh_mask.h): FORMAT, NUMBER_TYPE, COMP_SWAP, BLEND_CLAMP for UNORM, SNORM and SRGB, BLEND_BYPASS for UINT and SINT, and ROUND_MODE for the rest. Only those channel types and FLOAT are accepted. `GnmComponentSwapChannel` is the COMP_SWAP placement: STD, ALT, STD_REV and ALT_REV put 1 to 4 components as R, G, B, A / RG, RA, GR, AR / RGB, RGA, BGR, AGR / RGBA, BGRA, ABGR, ARGB, the codes Mesa's [ac_translate_colorswap](https://gitlab.freedesktop.org/mesa/mesa/-/blob/4fa244fddfebb21378042556862e197284ef65ac/src/amd/common/ac_formats.c#L566-625) gives for the formats it covers.
- [sceFontGraphicsGnmSurfaceInit format tables](../../../core/libs/prx/libSceFontGs/Export.cpp) (libSceFontGs) - `GnmElementBits` and `GnmComponentCounts` come from the channel widths in each IMG_DATA_FORMAT name of [gfx_7_2_enum.h](https://github.com/torvalds/linux/blob/d48723711bae9b8cdc56719c448ba42fef28cbee/drivers/gpu/drm/amd/include/asic_reg/gca/gfx_7_2_enum.h#L6049-L6113): BC formats are block bits over 16 texels, FMASK formats are their bit count with two components, GB_GR and BG_RG are 16 bits with three. The render-target number type keeps the texture channel type except Srgb 9 to 6 ([GnmConstant.h](https://github.com/Inori/GPCS4/blob/88480de36f983c66f7dd2c5951fead1a740d47a5/GPCS4/Graphics/Gnm/GnmConstant.h#L1760-L1810)).
- [sceFontGraphicsGnmDrawupFillTextureImage, sceFontGraphicsGnmDrawupFillTexturePattern, sceFontGraphicsSequenceGetGnmCommandsForChain and sceFontGraphicsSequenceGetGnmCommandsForSubmit](../../../core/libs/prx/libSceFontGs/Export.cpp) (libSceFontGs) - transliterated from the PS4 10.71 `libSceFontGs.sprx` bodies (offsets 0x40a0, 0x4150, 0x4580 and 0x4640; the names hash to `UsBLoyXsQZs`, `uksHKVEsxu4`, `NtbMKwRg6qg` and `DI4LrTUrD04`). They match the `libSceFontGs.native` AGC bridges except for the surface tag 0x48 and that the two sequence getters pass every error to `sceFontGraphicsReportError`. The sequence getters were matched by single PS4 runs on prepared sequences without a GPU submission; the drawup bridges and the PS5 exports with these NIDs were not checked on a console.
